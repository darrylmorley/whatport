Watch a connection happen

Plug something in and the port row now shows the connection being made: Detecting, then Negotiating, then the real thing. Plus a batch of Flight Recorder accuracy fixes.

## New

- **Connection lifecycle animation.** Ports used to sit idle for a beat and then pop fully-formed into "Thunderbolt 40 Gbps". WhatPort now listens to the notifications macOS fires while the connection is still coming up, so the row shows "Detecting" the instant a plug lands and "Negotiating" while the PD contract and link train. When the real data arrives, it fades in. On hardware that doesn't emit these notifications nothing changes, you get the old behaviour.

## Fixed

- **Flight Recorder no longer over-counts disconnects.** A Thunderbolt link renegotiating can look, for a single one-second poll, like the cable came out. The recorder wrote each of those as a real disconnect and reconnect, so one plug could log as three. Short-lived drops that come straight back are now recognised for what they are. A real unplug is still recorded, timestamped when it actually happened.

- **Launching the app no longer logs your attached devices as new connections.** A device that was already plugged in when WhatPort started is state, not news.

- **"Changed protocol N times" now means instability, not plugging things in.** A normal plug steps through USB before the Thunderbolt link finishes training, and the recap was counting every step. Protocol changes in the first seconds of a connection no longer inflate the count. The timeline still shows every step, because there they're informative rather than alarming.

## Install

Download below, unzip, and drag WhatPort.app to Applications, or:

```
brew upgrade --cask whatport
```

The app is signed and notarised by Apple.
